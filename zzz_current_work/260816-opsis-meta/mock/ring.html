content addressing: an applied edit is a NEW policy subject; the ring edge repoints; revert = re-read an old subject; "what changed" = two values diffed in the value room. the third tier is not drawn here: dragging any seam or toggling any control PATCHES this same record — direct manipulation and this room edit one truth.

THE RING — three tiers, one subject, no fourth mechanism. Direct (every control posts `set` against this record — dragging a seam IS editing settings), structural (slots with typed offers), textual (the record itself, refusing invalid states with the engine's words while the running policy stands). Because the record is content-addressed, settings history, revert and diff cost nothing the graph did not already pay. Room state (cameras, selectors) is deliberately NOT here — per-relation lifetimes stay per-relation; the boundary is drawn. The record is a file; a session boots by reading it; opsis's own configuration gets no privileged format.
