# S02: Grammar-Aware Parser — Research

**Date:** 2026-04-12

## Summary

S02 requires a `parse(text, grammar_path)` function that takes grammar-valid text and returns a typed Pydantic model instance. The approach uses Lark Earley at runtime, driven by the same GBNF grammar used in S01's `build()`.

The key challenge is: (1) converting GBNF to a Lark Earley grammar that actually compiles, and (2) mapping the Lark parse tree to the correct Pydantic classes generated by `build()`.

Three grammar transformation bugs must be fixed before Lark accepts any of the ground-truth grammars:
1. **`{n,m}` outside regex**: llguidance emits `/pat/{n,m}` but Lark requires `/pat{n,m}/` — move quantifier inside the regex.
2. **Adjacent regexes creating zero-width terminals**: `/[1-9]/ /[0-9]{0,15}/` → zero-width anonymous terminal `[0-9]{0,15}`. Fix: merge adjacent regexes into one: `/[1-9][0-9]{0,15}/`. Guard: don't merge when second regex is followed by a Lark quantifier (`* + ? ~`).
3. **Empty-string alternatives**: json_ws `ws: "" | " " | "\n" /[ \t]{0,20}/` → "Empty terminals not allowed". Fix: detect nullable rules from the GBNF AST (look for empty `SequenceNode` alternatives after `resolve()`), replace entire rule with `/[ \t\n]+/`, add `?` to all rule references.

## Recommendation

Implement `src/parser.py` with:
1. `_gbnf_to_earley_lark(gbnf_text)` — copy of with_guidance.py version (no model loading)
2. `_fix_lark_grammar(lark_g, gbnf_text)` — three-step fix described above
3. `_transform(tree, mods, gbnf_rules, text)` — recursive tree walker (NOT Lark Transformer) that maps Lark Tree nodes to Pydantic instances using `model_construct()`
4. `parse(text, grammar_path)` — public API

Use `propagate_positions=True` in Lark for literal-only terminal rules (e.g., `"int"`, `"char"`) that have no regex token children — text span extraction is the only way to recover their value.

### Core Transformer Logic

The `_transform()` function handles four rule body types:

**Terminal rules** (`gbnf_rule.rule_is_terminal = True`):
- If parse tree has Token children (regex-based): join tokens → str (gives content without surrounding quotes/literals)
- If no Token children (literal-only like `"int" ws`): use `text[meta.start_pos:meta.end_pos].rstrip()` from propagate_positions

**AlternativeNode rules** (abstract bases like `Value`):
- No non-ws subtrees: literal-only match (true/false/null) → use text span, find `XAltN` subclass
- Has subtree: check child rule name against `RuleRefNode` alternatives → find `XY` concrete subclass
- If no RuleRefNode matches: compare actual child rule names against `_seq_rule_refs(alt)` for each `SequenceNode` alternative, pick best match → instantiate `XAltN` subclass

**RuleRefNode body** (subclass rules like `Root(Object)`):
- Terminal ref → `value: str` field
- Non-terminal ref → copy fields from child instance

**SequenceNode / default** (sequence rules like `Object`, `Declaration`):
- Transform all non-ws children → flat list
- Consume from list using `_build_for_annotation(annotation, queue)` for each field

### `_build_for_annotation` — field value reconstruction

This function consumes from a child value queue to satisfy a Pydantic field annotation:
- `str` → pop one str
- `BaseModel subclass` → pop one instance
- `Optional[T]` → if `_can_consume(T, queue)`, recurse; else None
- `list[T]` → consume while `_can_consume(T, queue)` → collect
- `tuple[A, B, C]` → consume one for each type arg

Critical fix in `_can_consume` for tuples: count only non-`list` args as required (list args can produce `[]`). Without this fix, `Optional[tuple[str, Value, list[...]]]` with 2 items in queue would fail because 2 < 3.

## Common Pitfalls

- **`resolve()` naming**: after resolve, `root` → `start` in Lark grammar. In `_build_gbnf_rules()` for the parser, do NOT reverse this rename (unlike `build()` which does). The transformer maps `tree.data == 'start'` → `mods.get('Root')`.
- **Zero-width regex merge guard**: `r'/([^/]+)/ /([^/]+)/(?![*+?~])'` — the negative lookahead prevents merging when the second regex has a Lark quantifier after it (arithmetic `ident: /[a-z]/ /[a-z0-9_]/*`).
- **Nullable rule detection**: check for `SequenceNode` with no nodes (empty sequence), not just `LiteralNode('')`. After `resolve()`, ws's alternatives are `SequenceNode([]) | LiteralNode(' ') | SequenceNode(...)`.
- **model_construct()** everywhere: `model_construct()` bypasses Pydantic validation, required since generated field types like `Optional[tuple[str, Value, list[...]]]` can't be validated against reconstructed values.
- **chess/japanese String is non-terminal**: chess has `String(BaseModel)` with `items: list[...]` (individual chars), not `str`. `StringValue(Value)` has `string: String`, not `value: str`. The transformer handles this via the non-terminal RuleRefNode branch.

## Results

All 6 ground-truth grammars parse correctly:
- `json_ws`: Root with `strings: tuple[str, Value, list[tuple[str, Value]]]`
- `arithmetic`: Root with `items: list[tuple[Expr, Term]]`
- `list`: Root with `items: list[str]`
- `chess`: Root with chess-JSON structure, String as non-terminal
- `japanese`: Same structure as chess
- `c`: Root with Declaration including typed statement subclasses (StatementAlt3 for return)
