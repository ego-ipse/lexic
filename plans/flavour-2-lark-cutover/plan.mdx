# Drop Lark: a pure-`IrSelf` `flavour_2` and the Earley cutover

**Outcome.** Remove Lark from Lexic entirely. Both places `compile.py` reaches for Lark today get replaced by the IR-native Earley pipeline that already lives in `src/lexic/parsing_2/`, driven by a new **`flavour_2`** that is *pure IR data* — only `IrSelf` instances, no Python methods and no callbacks. When this lands, a flavour is **concrete syntax + surface rendering + escape data**, all expressed as IR; the fold from text back to IR is generic and shared.

**Why now.** The Earley engine (recognizer, parser, reducer, ABNF self-hosting fixpoint) is built, committed, and green at 977 tests. It is still standalone — nothing in the runtime path uses it. This plan is the wiring: turn a finished engine into the only parser, and delete Lark.

**Status.** Design settled (already hardened by one adversarial review pass). Implementation not started. This is multi-phase, multi-file, and contains genuinely hard-to-reverse structural decisions (the flavour table shape, the canonical-tag mechanism) that are called out explicitly below and must be decided before the grammars are authored.

</RichText>

<Callout id="callout-reuse" tone="info">

**Lead with reuse.** Several pieces already exist and are *reused*, not invented: `IrEscape` (`src/lexic/ir/flavour.py:23`) does the escaping; `IrMap` (`src/lexic/ir/mapping.py:81`) replaces `EscapeCodec`; `IrRange` (`src/lexic/ir/nodes.py:103`) is one of the `IrMake` targets. The genuinely new algebra in Phase 1 is the numeric/construction family (`IrRadix`, `IrChr`, the rest of `IrMake`) and the **selection/filter** family (`IrSelect`/`IrFilter`/`IrCollect`).

</Callout>

<RichText id="hard-to-reverse">

## The decisions that are expensive to undo

These are the bets that data and callers will depend on. The SPPF/ambiguity contract stays a hard engine prerequisite; the table shape and the canonical-tag mechanism are now decided (below) and both land on what `abnf_2` already ships.

</RichText>

<Callout id="callout-decision-ambiguity" tone="decision">

**Ambiguous grammars are supported (wire-level engine contract).** The engine must produce a **shared packed parse forest (SPPF)**. Today `chart.py`'s `Link` is single-valued — a placeholder that silently keeps the first completion. SPPF is a hard prerequisite for Seam 2 (user grammars may be ambiguous); it is *not* needed for Seam 1 or the grammars-of-grammars, which are unambiguous. This is why Phase 4 gates Phase 6.

</Callout>

<Callout id="callout-decision-table" tone="success">

**Decided — two tables.** Emit `actions` are keyed by IR node **type**; reductions are keyed by **rule name**. This is already the shape `abnf_2` ships: `ABNF_ACTIONS` is type-keyed and `ABNF_REDUCTIONS: IrMap[IrRuleRef, IrSelf]` is rule-name-keyed (26 reductions for ~11 types). A single bidirectional table would need a rule-name ↔ IR-type bijection that does not exist — many rule names reduce to one type, and emit needs only one body per type — so one table forces an artificial reconciliation and buys nothing. Revisit only if a future flavour shows a concrete need.

</Callout>

<Callout id="callout-decision-tag" tone="success">

**Resolved — the canonical tag *is* the rule name, keyed by `IrRuleRef`.** No new slot on `IrRule`, no separate side table. `abnf_2` already keys reductions on rule name through `IrRuleRef`: `ABNF_REDUCTIONS` maps `IrRuleRef("rule") → body`, `IrRuleRef("alternation") → body`, and so on. The grammar-of-grammar is authored so each rule name corresponds to one reduction body; that name is the tag. The only residual Phase-3 check is whether GBNF can be authored the same one-rule→one-reduction way — it can, by giving arms that produce different IR types their own named rules. (The handover flagged this as an open design point; in practice `abnf_2` has already closed it.)

</Callout>

<RichText id="phase-order">

## Phase order

Ordering principle: **build the algebra → fix the flavour container → author the grammars → SPPF → wire Seam 1 → wire Seam 2 → cut over.** The container precedes the grammars because GBNF forces representation decisions (escapes, `[...]`+`^` negation, postfix/`{n,m}` quantifiers) that ABNF's `%x`-only notation dodged. SPPF moves *after* the unambiguous-grammar work and *before* Seam 2, the only consumer that needs it.

<RichText id="phase-1">

## Phase 1 — IR algebra (`ir/`)

The enabling layer. Two families, both generic and unit-tested at the `eval` contract before anything downstream consumes them. **Do not touch `ABNF_REDUCTIONS` here** — the `parse_*` deletion is one atomic edit and belongs in Phase 3.

- **Numeric / construction:** `IrRadix` (digit-run → `IrInt`, base read structurally), `IrChr` (codepoint-carrying char leaf, emit-time spelling), and an `IrMake`-family constructing typed IR (`IrQuantifier`, `IrRange`, `IrCharClass`, `IrItem`, `IrSequence`, `IrAlternation`, `IrRule`, `IrAst`) from reduced children.
- **Selection / filter:** `IrSelect` / `IrFilter` / `IrCollect` (working names). The reductions don't only construct — they *filter children by type* and *positionally select* (`next(c for c in nc if isinstance(c, X))`, `nc[1:-1]`). Without these the `IrCallable`s cannot be removed. **This is the half an earlier draft omitted.**

</RichText>

<Callout id="callout-layering" tone="warning">

**Layering watch.** Type-filtering is *consumer policy*. Landing it in `ir/` risks cementing exactly the closed-set `isinstance` ladder the open-classes direction wants to dissolve (the open-set-consumer rework). Keep these nodes open and dispatch-driven, not a new hardcoded ladder. This is the single biggest design hazard in the whole effort.

</Callout>

<RichText id="phase-2">

## Phase 2 — `flavour_2` container + representations

Define the ABC with the pure-`IrSelf` shape, then resolve the representation questions ABNF never exercised because GBNF will.

- **Table shape** — two tables (decided): emit keyed by IR type, reduce keyed by rule name. Matches what `abnf_2` already ships.
- **Escapes** — `EscapeCodec` → `IrMap`/`IrSelf` data; escaping via the existing `IrEscape` node. Needed before any escaped-literal grammar (GBNF).
- **Char-class-with-escapes and `IrNot`, in *both* directions.** ABNF `%x`-only never exercised `[...]` escapes or negation; GBNF does (`[^"\\\x00-\x1F]`). There is **no `IrNot` reduction anywhere yet.**
- **Quantifier construction** for prefix (ABNF `*`, `1*`) *and* postfix + counted (GBNF `*`/`+`/`?`/`{n,m}`).
- **Case-insensitive literals** — handled by **algebraic per-char case-class expansion** (decided): each cased letter expands to a two-element char class at construction via the Phase-1 algebra — no dedicated node, no generic post-pass. `ABNF_GRAMMAR` was authored to dodge this; real ABNF input triggers it.

</RichText>

<RichText id="phase-3">

## Phase 3 — canonical-tagged grammars + shared reductions

- The canonical tag is the rule name (resolved above), so the keying mechanism already exists — **migrate `ABNF_REDUCTIONS` onto the shared table as-is** (it is already an `IrMap[IrRuleRef, IrSelf]`), dropping every `IrCallable` (currently 18) and every `parse_*` call **atomically**, in one edit. Re-close the ABNF fixpoint. Delete the emit-side `_abnf_charclass` `IrCallable` including its parenthesize-iff-multiple branch.
- Author the **GBNF grammar-of-grammar** (`gbnf_2.py`) on the same tags + shared reductions; it now has the escape/negation/quantifier machinery from Phase 2. Close its self-hosting fixpoint. Reproduce **`CORE_RULES` injection** (undefined `ALPHA`/`DIGIT`/`CRLF`…) here or in Phase 5.

</RichText>

<RichText id="phase-4">

## Phase 4 — SPPF / ambiguity (gates Seam 2)

- Make `chart.py` `links` multi-valued; `build_tree`/`forest.py` produce **packed nodes**; `ParseTree.kids` admits them.
- `Reducer._reduced_children` must handle packed nodes plus a disambiguation policy — this *does* ripple into `reduce.py`. Add an ambiguity-detection path (today the chart silently keeps the first completion).
- Disambiguation policy lives at **grammar-author level** (decided): the author resolves ambiguity, so the engine and flavour stay policy-free. (Sequencing note: this needs an author-facing surface for expressing the policy — decide that shape during Phase 4, since no such surface exists today.)
- Tests with a deliberately ambiguous grammar.

</RichText>

## Phase 6 — Seam 2 (runtime input → `GrammarModel`)

The single largest, least-specified piece. It is **not** "reuse the Reducer with a different target" — it is re-deriving `build_transformer` as reduction bodies. Re-express, as `IrSelf` reductions driven by `RuleSpec`: `field_map`/`kind`-driven field assignment, unquantified-literal skipping, unbounded→list, per-atom consumers, and the adjacent optional-ruleref type disambiguation. That last one is the subtle bit — here is the exact logic the reductions must reproduce:

<RichText id="phase-7">

## Phase 7 — cutover / cleanup

- Delete `parsing/lark_builder.py`, `parsing/meta_parser.py`, `parsing/transformer/`, the `META_GRAMMAR` strings, `EscapeCodec`, and the Lark dependency.
- **Redesign `CompiledGrammar`** — it currently holds `lark.Lark` / `lark.Transformer` typed fields (`compile.py:55-61`); the shape must change, not just lose imports.
- Rename `parsing_2 → parsing`, `flavour_2 → flavour`, `abnf_2 → abnf`, etc., and mirror the test tree (test files move exactly as their source files do).
- Finish the deferred `utils/quantifiers.py` cleanup (still consumed by `lark_builder` and `codegen/aliases.py`).
- Update `CLAUDE.md`, `.wiki/`, the layering rules, and `prototyping/next/3_ROADMAP.md`.

</RichText>
